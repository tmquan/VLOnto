# Language layer: EN · VI · EN–VI (`site/js/i18n.js`)

Every page of the website has a three-way language switch in the header. It shows the whole interface in English
(EN), in Vietnamese (VI) or bilingual (EN–VI, the default, the look of v1). The layer is a classic script, works from
`file://` and over `http://` in Chrome, Safari and Firefox, and follows the rules of the theme toggle (`js/common.js`,
`js/doc-theme.js`).

This file is the contract for the two page tracks of phase 2 (the 3D track and the content-pages track). Phase 1
built the layer, the switch, single-language navigation and chrome, and the dictionaries with the Vietnamese of every
interface string. Phase 2 wires the page scripts and page markup to the dictionaries.

## Modes

| Mode | Switch | Navigation, buttons, labels | Content: legends, call-outs, panel values, titles, glosses | Running text, headings | `html[lang]` |
|---|---|---|---|---|---|
| `en` | EN | English | English; the Vietnamese original where there is no English (most document titles) | English | `en` |
| `vi` | VI | Vietnamese | Vietnamese | Vietnamese | `vi` |
| `envi` (default) | EN–VI | English, with the Vietnamese as a tooltip (`title`) | pairs **Tiếng Việt · English**: Vietnamese first, English muted | English | `en` |

The navigation never mixes the two languages: it reads **Traces** in EN and EN–VI (tooltip *Truy vết* in EN–VI) and
**Truy vết** in VI. The v1 label "Truy vết · Traces" is gone in every mode.

The playbook text and the pyLODE ontology reference stay English. In VI the pyLODE reference shows the one-line note
*Tài liệu tham chiếu này chỉ có bằng tiếng Anh.* The playbook and ontology page shells have their notes in the
dictionary (`pb.englishOnly`, `ontp.englishOnly`); the content-pages track places them (shown in VI only).

**Why `html[lang]` is `en` in EN–VI.** In EN–VI the chrome and the running text are English, and every Vietnamese
fragment is marked `lang="vi"` (`VL.TH`, `VL.UH` and `data-i18n` add it). Screen readers and hyphenation then switch
language per fragment. Rejected alternatives: `vi` (the English chrome would be read with a Vietnamese voice),
`vi-x-en` (a private-use tag that screen readers do not map to any voice) and `mul` (no voice either). A document that
stays in one language whatever the mode (the pyLODE reference) loads the layer with `data-doc-lang="en"`; its
`html[lang]` stays `en`, and only its bar follows the mode.

## State and persistence (the same rules as the theme)

1. The mode comes from `?lang=en|vi|envi`, else the stored choice (`localStorage['vlonto.lang']`), else `envi`.
2. A choice made with the switch is stored where storage works.
3. Internal `.html` links carry `?lang=` (added on click, other parameters and `#hash` kept) when the mode came from
   the URL, or once a mode is chosen under `file://` (Firefox and Safari keep file storage per file) or with storage
   blocked. Scripts that navigate use `VL.href(h)`, which adds `theme=` and `lang=` the same way.
4. When the mode came from the URL or storage is blocked, `history.replaceState` keeps `?lang=` in the address bar, so
   a reload keeps the mode.
5. Other open pages follow through the `storage` event.
6. Embedded documents follow through `postMessage`. The parent sends `{type: 'vlonto-lang', lang}` to its iframes on
   load and on every change. An embedded document asks once with `{type: 'vlonto-lang-request'}`. Children accept
   messages only from `window.parent`, and parents answer only their own iframes.

## API (`window.VL`)

| Call | Returns / does |
|---|---|
| `VL.LANGS` | `['en', 'vi', 'envi']` |
| `VL.lang()` | the current mode |
| `VL.setLang(mode, {store})` | Switches the mode and returns `true` if it changed (`false` for an invalid mode). `store` (default `true`) remembers the choice; pass `false` for changes that follow another page. Fires `vl:lang`. |
| `VL.T(x, vars)` | Plain text: `"vi · en"` in EN–VI (when both exist and differ), else one language. Falls back to the other language where the mode's is missing. |
| `VL.U(x, vars)` | Plain text in one language (EN–VI → English). Use it for navigation, buttons, labels and sentences. |
| `VL.tip(x, vars)` | The Vietnamese tooltip of a control in EN–VI, `''` in the other modes. |
| `VL.TH(x, vars, opts)` | HTML: in EN–VI `<span lang="vi">…</span> · <span class="en" lang="en">…</span>`, else one language, marked `lang="…"` where it is not the page language. `opts.sep` and `opts.enClass` adjust the pair; `opts.html = {name: '<a …>…</a>'}` puts raw HTML into `{name}` placeholders after escaping. |
| `VL.UH(x, vars, opts)` | HTML of `VL.U`, with `lang="…"` where needed (`opts.html` as above). |
| `VL.TL(x, vars)` | Lines for 3D sprites and call-outs: `{primary, secondary, primaryLang, secondaryLang}`. In EN–VI: primary = Vietnamese, secondary = English gloss. In EN or VI: one line (`secondary: ''`, `secondaryLang: null`). |
| `VL.pair(vi, en)` | `{vi, en}` (NFC), so that data fields go through the same helpers: `VL.T(VL.pair(n.label_vi, n.label_en))`. |
| `VL.withLang(href, mode)`, `VL.carryLang()` | Set `lang=` in a URL; whether internal links must carry it now. |
| `VL.langSwitch({labelledby, className})` | A new switch element (all switches on a page stay in sync). |
| `VL.i18n.add(owner, entries)` | Registers dictionary entries (the dictionary files call it). |
| `VL.i18n.apply(root)` | Applies the declarative attributes inside `root` (call it after inserting markup that uses them). |
| `VL.i18n.has(key)`, `.get(key)`, `.keys(owner)`, `.missing()`, `.htmlLang()` | Introspection: `get` returns `{en, vi, k, owner}`. `missing` lists the keys asked for that no dictionary has; the page shows the key name instead. |

`x` is a dictionary key or a `{vi, en}` object (a `VL.pair`, a `VL.MODULES` / `VL.VALIDITY` record, a data record).
`vars` fills `{name}` placeholders. A value is text, or a `{vi, en}` object whose text of the same language goes in:
`VL.T('net.more', {n: rest})`, or `{name: VL.pair(n.label_vi, n.label_en)}` for a value that has both languages. The
entry's `en_one` is the English used for `{n: 1}`.

## Dictionary entries

```js
'key': { en: 'English', vi: 'Tiếng Việt', k: 'ui' | 'text' | 'pair', en_one: 'English for n = 1' }
```

| Kind (`k`) | For | EN | VI | EN–VI |
|---|---|---|---|---|
| `ui` | navigation, buttons, tabs, field labels, `aria-label`s | English | Vietnamese | English, Vietnamese tooltip |
| `text` (default) | headings, sentences, status lines, notes | English | Vietnamese | English |
| `pair` | legends, call-outs, panel values, titles, glosses | English | Vietnamese | `Tiếng Việt · English` |

Rules for every entry:

- NFC text with full diacritics. The `{placeholders}` must be the same in `en` and `vi` (`en_one` may drop some).
- Legal and ontology terms use the ontology's own Vietnamese labels (`ontology/vlonto.ttl`, `rdfs:label` /
  `skos:prefLabel @vi`). Examples: legal basis = *căn cứ pháp lý*, document number = *số, ký hiệu văn bản*, issued by
  = *cơ quan ban hành*, issue date = *ngày ban hành*, effective date = *ngày có hiệu lực*, expiry date = *ngày hết
  hiệu lực*, validity status = *tình trạng hiệu lực*, source status = *tình trạng theo nguồn*, legal-force rank =
  *thứ bậc hiệu lực pháp lý*, rank level = *bậc*, legal term = *thuật ngữ pháp lý*, module = *mô-đun*, amends =
  *sửa đổi, bổ sung*, repeals = *bãi bỏ*, partially repeals = *bãi bỏ một phần*, replaces = *thay thế*.
- The site's existing Vietnamese wording wins: *tư vấn pháp lý*, *Bảng điều khiển*, *Tải xuống*, *Sổ tay*,
  *Truy vấn SPARQL*.
- Navigation labels stay short: the header has a width budget (see Layout).

Key prefixes and owners:

| File (owner) | Prefixes | Strings of |
|---|---|---|
| `js/i18n.js` (`i18n`, core, 55 keys) | `chrome.*`, `common.*` | header, navigation, menu, switch, theme toggle, footer, footbar, skip links, pyLODE bar, shared panels of `common.js` |
| `js/i18n-3d.js` (`i18n-3d`, 350 keys) | `net.*`, `o3d.*`, `tr3d.*`, `tdraw.*`, `sq.*`, `sqc.*` | `network3d.js` + `network-3d.html`, `ontology3d.js`, `traces3d.js`, `trace-draw.js`, `sparql-page.js` + `sparql.html`, `sparql-core.js` (`paper3d.js` and `labels3d.js` have no interface strings) |
| `js/i18n-pages.js` (`i18n-pages`, 376 keys) | `play.*`, `traces.*`, `o3dr.*`, `dash.*`, `about.*`, `dl.*`, `pb.*`, `ontp.*` | `index.html` (side panel, filters, hint, query drawer), `traces.html`, `ontology-3d.html`, `dashboard.html` + `dashboard.js`, `about.html` + `home.js`, `downloads.html` + `downloads.js`, `playbook.html` + `playbook.js`, `ontology.html` + `ontology-page.js` |

For 578 of the 726 entries of the two track dictionaries, the English was found verbatim in the current (v1) source
of its page. The other 148 are templates for strings the scripts compose (counts, names, plurals) or split v1 pairs,
and were written from the composing code. A track that changes an English text in its page changes the entry too.

## Declarative markup (static HTML)

| Attribute | Effect |
|---|---|
| `data-i18n="key"` | The element's text (for an element without child elements): one language, or the pair HTML for keys of kind `pair`. Kind `ui` adds the Vietnamese `title` in EN–VI. |
| `data-i18n-kind="ui\|text\|pair"` | Overrides the kind of the key for this element. |
| `data-i18n-title="key"` | `title`, as `VL.T` (`"vi · en"` in EN–VI). |
| `data-i18n-aria="key"` | `aria-label`, as `VL.U`. |
| `data-i18n-placeholder`, `data-i18n-alt`, `data-i18n-content` | `placeholder`, `alt`, `content`, as `VL.U`. |
| `data-i18n-vars='{"n":3}'` | Placeholder values (JSON). |
| `data-vl-text` | Text that a page script writes (sentences with links or numbers, descriptions). Hidden while the page loads (`html.vl-i18n-boot`) until the script has put in the mode's text and set `data-vl-text="ok"`; shown at `DOMContentLoaded` whatever happens. `data-vl-text="wait"` (chart captions) stays hidden until its first text, since it means nothing without the chart. |

The layer owns the `lang` attribute of a `data-i18n` element (set where its text is not in the page language). It also
owns the `title` of a `ui` element that has no `data-i18n-title`. A successfully applied element gets
`data-i18n-ok`. While the page loads (`html.vl-i18n-boot`), elements with `data-i18n` stay hidden until their text is
in, so no wrong language flashes. At `DOMContentLoaded` everything shows, and a key no dictionary has shows the
markup's own text. Keep the English text in the markup: it is what shows without scripts.

## Re-rendering: the `vl:lang` event

`VL.setLang` sets `html[data-lang]` and `html[lang]`, re-applies the declarative attributes, then fires `vl:lang` on
`document` with `detail = {lang, previous}`. Pages re-render what they built in script (legends, panels, call-outs,
3D labels, tooltips, status lines) without a reload, and keep the selection, camera, query and scroll position:

```js
document.addEventListener('vl:lang', function () {
  renderLegend();              // rebuilt with VL.TH / VL.U
  if (state.selected) showPanel(state.selected);
  labels.refresh();            // 3D sprites from VL.TL
  VL.i18n.apply(panel);        // markup with data-i18n inserted by the script
});
```

`common.js` already re-renders the header, footer, footbar, theme-toggle labels and paper blocks this way.

## The switch

`VL.langSwitch()` builds `<div class="vl-lang" role="radiogroup">` with three `<button role="radio" data-vl-lang="en|vi|envi">`
showing the language-neutral codes **EN**, **VI** and **EN–VI**. Each button's `title` names the mode in the current
language; the group's label is *Language* / *Ngôn ngữ*. It uses a roving `tabindex`: Tab enters the group at the
checked mode, the arrow keys move and select, and Tab leaves. `common.js` puts one switch in the header next to the
theme toggle (`.vl-lang-bar`). It puts a second one in the menu sheet under the pages (`.vl-lang-row`, labelled by
`#vl-lang-label`); that one is shown on phones (≤ 600 px), where the header has no room. The segments are 28 px high,
so the two-tone focus ring and its 6 px halo stay inside the header. No ancestor clips them.

The buttons use `data-vl-lang`, never `data-lang`: `html[data-lang]` is the mode. The 3D pages' own label toggles
use `button[data-lang]` and their selectors are scoped to buttons (`ontology3d.js`, `network3d.js`).

## CSS (`css/site.css`)

- Core (phase 1, frozen): the switch and header breakpoints in the header section, and the section
  "language layer". Pair markup reads `--pair-en` for the muted English, with zero specificity
  (`:where(span.en[lang="en"])`), so a view's own rule for its pairs wins.
- Mode-specific rules: `:root[data-lang="vi"] .x { … }`, `:root:not([data-lang="vi"]) .x { … }`.
- **Track sections.** Each track adds rules only between its two markers. The sections are about 280 lines apart, so
  the two tracks merge without conflict; a simulated merge of both, in either order and with `git merge-tree`, was
  clean.
  - `/* ===… CONTENT-PAGES TRACK: language (phase 2)` … `/* ===… end of CONTENT-PAGES TRACK */` (before "scene docking")
  - `/* ===… 3D TRACK: language (phase 2)` … `/* ===… end of 3D TRACK */` (end of the file)

A track edits only its own dictionary. A string used by both tracks goes into the dictionary of the file that renders
it. After editing a dictionary, run:

```
python3 scripts/site/i18n_check.py --root site            # errors: exit status 1
python3 scripts/site/i18n_check.py --root site --unused   # keys no page or script uses yet
python3 scripts/site/i18n_check.py --root site --csv translations.csv
```

The checker parses the three dictionaries and reports keys defined twice, unknown fields or kinds, empty texts,
non-NFC values and placeholders that differ between `en` and `vi`. It also reports every literal key a page or script
uses (`data-i18n*` attributes, `VL.T/U/TH/UH/tip/TL('key')`, `'prefix.' + x` counts as a prefix) that no dictionary
defines.

## Layout budget (header)

These are estimated with a model built from the advances of the embedded Be Vietnam Pro faces at the CSS sizes. The
same model gives 1,352 / 1,264 px for the v1 header, whose measured widths were 1,352 / 1,263 px.

| Mode | With tag line | Without | Tablet (menu) | Phone |
|---|---|---|---|---|
| EN, EN–VI | 1,404 px | 1,316 px | 426 px | 279 px |
| VI | 1,511 px | 1,401 px | 455 px | 308 px |

The tag line goes below 1,430 px (VI: 1,540 px), and the pages move into the menu below 1,340 px (VI: 1,430 px).
From 320 to 1,920 px the header never overflows. The smallest margin is 24 px (EN at 1,340 px) and 12 px (VI at
320 px); a classic 17 px scrollbar leaves at least 7 px. At 1,440 px the margin is 36 px (EN, EN–VI) and 39 px (VI).
The scene footbar fits in every mode: one line above 1,180 px, at most two lines on tablets, and on phones up to three lines
(VI from 320 to 375 px, out of a room of 2.96 lines). A longer navigation label needs a new estimate.

## Decisions and open points

- Numbers keep the site's `40,816` format in every mode. Vietnamese writes `40.816`; changing it is the lead's call.
- Rank labels use *bậc* (the ontology's `vlo:rankLevel`); the v1 network legend said *Hạng*.
- The 3D pages' per-view label toggles (`button[data-lang]`, VI / EN labels in the scene) remain. The 3D track
  decides whether they become a per-view override of the global mode or go. The CI test
  `scripts/site/interaction_tests.py` clicks `[data-lang=vi]`. That still finds the button in the default mode; a
  run with `?lang=vi` would match `<html>` first, so the selector should then be `button[data-lang=vi]`.
- `sparql.html` says "The full graph (31.5 million triples)", but the v1 statistics give 6,963,753 RDF triples. The
  key `sq.know.full` takes `{n}`; the 3D track should fill it from `VLONTO.stats`.
- Content pairs such as "Đường truy vết · Traced path" stay until the tracks convert their views to the modes.
- Not tested in phase 1: real browsers (an offline DOM run covered all pages in all modes at 1,440 and 390 px under
  `file://`), contrast in every mode, and screen readers.
